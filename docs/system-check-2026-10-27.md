# 시스템 연결 시험 기록 — 2026-10-27

UI 개편과 노트북 이전은 제외했다. 실제 공개 기사 1건, 완성 주간호 0개 상태를 유지했다. 시험 PDF나 시험 원고를 실제 공개 데이터에 발행하지 않았다.

## 이번에 연결한 기능

- 검토된 주간호 JSON → 한국어 글꼴을 포함한 A4 50페이지 PDF. 표지·발행인의 말·목차·판권 4면, 본문 46면, 2단 본문, 기사 이미지·캡션·출처 링크·QR 포함.
- 본문 넘침을 실패로 처리하고 조판 중간 파일을 정리한다. 빈 지면을 추가하거나 원고를 잘라 페이지 수를 맞추지 않는다. 분량·여백·기사 구성의 편집 판단은 별도다.
- 출고 시 PDF를 직접 파싱하고 A4·페이지 수·텍스트 존재를 검사한다. 원고와 이미지 파일 지문, PDF 파일 해시를 대조한다. 시험 PDF와 검수 이후 변경된 원고는 출고할 수 없다.
- 발행호 웹 열람은 홈페이지 최신 기사와 분리된 스냅샷을 사용한다. 미발행 PDF는 정적 배포에서 제외한다. 발행된 호 ID의 PDF 재생성·덮어쓰기를 금지한다.
- 홈페이지 기사 출고 시 실제 로컬 이미지 존재도 검사한다. 수집 작업의 임시 루트가 실제 작업 루트와 일치하도록 수정했다.
- 기본 pipeline 명령은 실제 제작 상태를 보고한다. 레거시 지면 갱신을 자동 발행 완료로 안내하던 경로를 제거했다.

## 검증

`npm test`: 20개 자동 테스트 통과. 기존 기사 열람·저장·검토·출고·잠금·수집 실패 정리와 새 PDF·웹 발행호·정적 내보내기를 포함한다. Windows 샌드박스에서 임시 파일 교체와 localhost 접속 제한에 걸렸던 시험은 필요한 권한으로 재실행했다.

`npm run check:edition`: 50페이지 시스템 시험 PDF 생성, A4 및 텍스트 존재 확인. 전 면을 PNG로 렌더링한 두 개의 접촉 인화와 기사 첫 면·본문 확대를 확인했다. 한글·삽화·QR·단 나눔에서 겹침이나 잘림은 보이지 않았다. 시험 문단 분량이 적은 면의 여백이 크므로 이 결과는 실제 주간지의 지면 품질 승인으로 사용하지 않는다.

`npm run build`: 공개 데이터 정적 패키징 성공. Python은 제작·출고 PC에서 필요하며 정적 배포의 구조 검사 재확인은 출고 시 기록과 파일 해시로 수행한다.

## 아직 전체 운영 완료가 아닌 이유

1. 실제 주간호 기사 14개 집필·추가 취재·재편집·지면 검수와 첫 실발행이 남아 있다.
2. Gemini·Claude·GPT의 정기 무인 인계, 로그인·사용량 제한 발생 시 복구, 예약 실행은 연결 전이다.
3. 주간 방송 자동 선별, 스틸·Heatmap 추출은 미완성이다.
4. 이번 통합 시험의 원문 수집은 모의 입력을 사용했다. 실제 방송 음성 인식은 이전 시험에서 확인했으며 이번에 반복하지 않았다. 현재 수집 작업에는 실제 자료 5건이 남아 있다.

다음 실운영 검증은 실제 방송 한 편의 근거 분석 → 기사 집필·이미지 → 출고를 새 절차로 수행하고, 이어 주간 14개 꼭지를 완성하는 것이다. 프로그램 테스트 통과와 편집 품질 검수 완료를 구분한다.
