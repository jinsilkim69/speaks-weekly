# 정기 제작 실행 지침

이 지침은 이 채팅의 정기 실행에서 사용한다. 집필은 2026-10-27 사용자가 재정립한 ‘방송 핵심 전달·이해를 돕는 설명·텍스트 기록’의 정체성을 최우선으로 한다. 사용자 승인 범위는 실제 원문을 읽고 분석·집필·검수하여 홈페이지와 주간지를 발행하고 GitHub/기존 Cloudflare 사이트에 반영하는 일이다. UI·PDF 조판은 검수한 최신 편집 기준을 적용하고 다른 PC로의 이전은 보류한다. 유료 API를 추가하지 않는다.

## 실행과 중복 방지

1. 저장소의 AGENTS.md, 집필 스킬, docs/editorial-operations.md를 읽는다. `node scripts/production-cycle.mjs begin daily` 또는 `begin weekly`로 사이클을 시작한다. skip=true면 중복 실행하지 않는다.
2. active가 오래된 running 상태면 실제 실행 프로세스와 이미 생성된 결과를 확인한다. 확인 후 실패 결과 JSON(id,state:failed,summary,steps)을 만들어 finish로 기록한 뒤 재시도한다. 실행 중인 작업을 강제로 덮어쓰지 않는다.
3. 끝날 때 id,state(completed/failed),summary,steps([{action,result}])를 결과 JSON에 적어 `node scripts/production-cycle.mjs finish 결과.json`으로 기록한다. 완료는 그 실행에서 실제 수행한 작업의 완료이며 항상 발행을 의미하지 않는다. 자료 부족으로 출고하지 않은 경우에도 구체적 근거와 후속 작업을 남긴다.

## 매일 09:00·15:00·18:00 KST

- 전날부터 현재까지의 공식 스픽스 방송·신문 새 자료를 찾는다. 매 회차 `npm run editorial:prepare -- daily 기준일 --refresh`로 새 후보를 갱신한다. prepare daily는 기준일의 전날을 대상으로 하므로 오늘 자료는 다음 날짜를 asOf로 사용한다. 현재 진행 중인 생방송을 완성 방송으로 분석하지 않는다.
- 후보를 직접 골라 editorial:collect로 본문/자막을 수집한다. 같은 URL·ID·내용은 재사용하고, 목록 중복·403·짧은 원문 연결 페이지만 있는 경우에는 추가 취재 대기로 둔다. 주어진 기간 밖 자료는 배경으로 명시한다.
- 홈페이지 제작 단위는 코너별 방송 회차다. 코너명·실제 방송일·진행자·출연자·원방송을 먼저 식별한 뒤 그 회차의 핵심 결론·주장·이유·사례·이견을 소개한다. 한 방송의 여러 주제를 각각 독립 기사로 쪼개 코너와 회차의 맥락을 없애지 않는다. 원문 부족이면 소개 완료로 표시하지 않는다. 같은 회차에서 나온 본방송·재방송·클립은 연결해 중복 집필을 막는다. 실제 방송일과 고정 편성 요일은 구분하며 고정 편성은 공식 확인 뒤 표시한다. 신문 기사는 보충 읽을거리로 구별한다.
- Gemini 구독 웹 앱은 CUA로 사용한다. 기본 입력은 실제 확보한 자막·기사 본문과 시간표시이며, 자료 범위를 명시해 분석을 요청한다. 영상 링크만 전달한 요청이 지연되면 확보 텍스트를 나눠 전달하는 경로로 전환한다. 각 요청에서3분 이상 응답이 없거나 로그인·한도가 막히면 중단하고 실패를 기록한다. 이 경로도 실패하면 GPT가 원문 대조 분석을 대행하고 실제 작업자를 남긴다. Gemini의 접근 범위가 제공 텍스트뿐이면 영상·음성 분석 완료라고 적지 않는다. 응답은 원자료와 다시 대조하며, 통계의 결측·반올림 원인이나 법적 의무를 추측한 제안은 그대로 채택하지 않는다.
- Claude 구독 CLI는 scripts/claude-desk.mjs로 실행한다. 요청.json에는 id,articleIds,prompt를 둔다. 프롬프트에는 집필 스킬과 실제 원문, 주제별 요구를 포함한다. API 인증 환경변수는 자식 프로세스에서 제외한다. 구독 로그인·한도·실패는 명시적으로 기록한다. Claude가 불가하면 내장 GPT가 실제 집필을 대행하고 기록한다.
- GPT는 원문과 결과를 대조하여 핵심 내용 보존, 화자·주장·사실 구별, 쉬운 설명, 문체와 중복을 데스킹한다. 초기 원고를 검토 없이 승인하지 않는다. 이미지 종류와 논지를 맞춘다. 사진은 라이선스·촬영연도·맥락, 삽화는 AI 표시·프롬프트, 도표는 수치·범위를 확인한다.
- 홈페이지 회차 소개는 기존 긴 시안 대비 약 20% 축약하되 핵심·이유·대화 흐름은 보존한다. 표·그래프만으로 채우지 말고 주제와 관련된 사진·삽화를 보통 2~3장 편집한다. 기사에 episode(programId,videoId,url,broadcastDate,hosts,guests,durationSeconds)를 기록하고 data/programs.json의 코너에 연결한다. 코너·방송일·출연자 변경도 검토 해시에 포함된다. 고정 편성이 확인되지 않으면 schedule은 null을 유지한다.
- save → review → publish로 출고한다. 새 기능을 바꿨다면 관련 테스트, 실제 기사·이미지 검증, build, GitHub push, 공개 페이지 확인까지 수행한다. 검토가 끝난 기사·자산만 커밋하며 원시 자료·구독 인증정보·다른 사용자 변경은 포함하지 않는다.

## 일요일 18:00 마감·월요일 06:00 발행 KST

- 일요일에는 이번 주 월요일~일요일, 월요일에는 직전 월요일~일요일을 대상으로 검토된 원고와 시각자료를 마감한다. 50면은 고정 조건이 아니며 글의 완결성과 가독성에 필요한 만큼 페이지를 늘린다. 이미 발행된 호는 수정하지 않고 정정판 ID를 사용한다.
- 편집 중인 호에 서로 다른 질문과 근거를 가진 실제 원고를 편성한다. 방송의 논리와 대화 흐름을 보존하며 주제별로 재구성한다. 한 주의 핵심을 읽는 기록으로 남기고 편집부 비평이 중심을 밀어내지 않게 한다. 가짜 인터뷰·통계·댓글·서평, 분량 채우기 반복을 금지한다. 홈페이지 기사 전부를 그대로 합본하지 않는다.
- 14개 검토 원고와 발행인의 말로 edition:build를 실행한다. `python scripts/check-edition-render.py output/pdf/호ID/edition.json output/pdf/호ID/proof.pdf --output output/pdf/호ID/render`로 전 면 렌더링·원고 누락·글자 경계를 검사한다. 실제 이미지를 열어 한글, 페이지 넘침, 이미지, 단 나눔, 캡션, QR, 여백, 목차를 확인한다. 넘침은 원고·편성을 고치고 재조판한다. 실제 시각 검수 후에만 pdfReview를 작성한다.
- 완성 PDF만 public/editions에 복사하고 release-edition으로 출고한다. build/push 뒤 공개 PDF와 웹 발행호를 확인한다. 실제 수집·집필이 부족하거나 시각 검수가 끝나지 않았다면 미발행 상태를 유지하고 결함과 남은 취재를 보고한다.
- 전 면 렌더 검사는 `check-edition-render.py`, QR 14개 원출처 일치 검사는 `check-edition-qr.py`로 수행한다. PDF는 벡터 문서이므로 QR 검사는 3배 배율로 렌더링한다. 화면에서 축소한 접촉 인화만으로 QR의 정상 여부를 판단하지 않는다.

## 알림과 운영 조건

변화가 없거나 출고할 내용이 없으면 조용히 종료한다. 실제 새 발행, 의미 있는 실패, 구독 로그인/한도 등 사용자 조치가 필요한 상황만 알린다. 이 채팅의 정기 실행은 현재 PC와 앱이 켜져 있고 프로젝트 폴더를 사용할 수 있을 때 동작한다. 종료 중 놓친 작업은 다음 실행에서 마지막 완료 기록과 편집 중인 호를 확인해 이어 간다. 이 방식은 PC가 꺼진 동안의 서버 자동 발행을 구현했다는 뜻이 아니다.

- 홈페이지의 두 메뉴는 ‘스픽스 리뷰’와 ‘주간지 기사 보기’다. 리뷰는 월~일을 항상 펼치고 각 요일 아래 코너를 표시한다. 원본 영상 연결을 리뷰 옆에 둔다. 주간지 메뉴는 전주 대상 기간이 마감된 발행호의 최신 교정판 스냅샷을 그대로 제공한다. 고정 편성 근거가 없으면 실제 방송일 기준임을 명시한다.

## 모델 간 실제 제작 인계 규칙 (2026-10-27)

1. Gemini 구독 웹 앱에 구조화 원문을 전달해 핵심 주장·화자·시간·이견·미확인 날짜·시각자료 후보를 받는다. 영상 링크 전달과 실제 영상 청취를 동일하게 기록하지 않는다. 원문 텍스트만 읽었으면 그 범위로 남긴다. 응답이 중단되면 partial로 기록하고 완료 처리하지 않는다.
2. GPT는 조사 메모를 원문과 대조하고 누락·오독을 보완하며 사진의 날짜·이용 조건, 삽화의 역할을 결정한다. 서비스 제한으로 대행한 원문과 이유를 기록한다. Gemini의 사실 단정이나 도표 제안을 그대로 채택하지 않는다.
3. Claude 구독 CLI에 원문과 조사 인계·GPT 교정 사항·이미지 기획을 전달한다. 먼저 초고를 병행 집필했어도 조사 도착 후 최종 집필·캡션 교정을 다시 수행한다. 결과는 초고/최종 데스크로 구분한다.
4. GPT가 최종 원고와 실제 이미지를 보고 검수한다. 출고 원고의 productionHandoff에 인계 JSON 경로를 기록한다. scripts/production-handoff.mjs의 assertProductionHandoff로 원문 SHA, 조사 완료/대행 범위, Claude 실제 완료 기록, 최종 원고·이미지 검토 해시를 검증한 뒤 save/review/publish한다. 인계 경로가 있는 원고는 publishDraft에서도 다시 검증한다.
5. 이번 표본은 Gemini 자막 조사 부분 완료·사용량 한도 → GPT 보완·이미지 제작 → Claude 최종 6편 교정 → GPT 출고 검수로 수행했다. 이것은 실제 서비스 구독 화면/CLI를 사용하는 에이전트 인계이며, 세 서비스의 완전 무인 자동 연결이 검증됐다는 뜻은 아니다.

요일별 목록에는 표시 주간을 명시한다. 이번 검수 표본은 2026.10.19~25이며 26일 회차를 섞지 않는다. 제목 날짜·공개일이 다른 회차는 방송 제목 기준 또는 공개일 기준임을 표시한다. 과거 방송의 전망은 당시 발언으로 남기고 뒤의 결과를 소급해 고치지 않는다. 빈칸을 채우려고 다른 요일 영상을 이동하거나 실제 방송 스케줄을 만들지 않는다.
