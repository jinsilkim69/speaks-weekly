# 정기 제작 실행 지침

이 지침은 이 채팅의 정기 실행에서 사용한다. 사용자 승인 범위는 실제 원문을 읽고 분석·집필·검수하여 홈페이지와 주간지를 발행하고 GitHub/기존 Cloudflare 사이트에 반영하는 일이다. UI 개편과 다른 PC로의 이전은 보류한다. 유료 API를 추가하지 않는다.

## 실행과 중복 방지

1. 저장소의 AGENTS.md, 집필 스킬, docs/editorial-operations.md를 읽는다. `node scripts/production-cycle.mjs begin daily` 또는 `begin weekly`로 사이클을 시작한다. skip=true면 중복 실행하지 않는다.
2. active가 오래된 running 상태면 실제 실행 프로세스와 이미 생성된 결과를 확인한다. 확인 후 실패 결과 JSON(id,state:failed,summary,steps)을 만들어 finish로 기록한 뒤 재시도한다. 실행 중인 작업을 강제로 덮어쓰지 않는다.
3. 끝날 때 id,state(completed/failed),summary,steps([{action,result}])를 결과 JSON에 적어 `node scripts/production-cycle.mjs finish 결과.json`으로 기록한다. 완료는 그 실행에서 실제 수행한 작업의 완료이며 항상 발행을 의미하지 않는다. 자료 부족으로 출고하지 않은 경우에도 구체적 근거와 후속 작업을 남긴다.

## 매일 09:00·15:00·18:00 KST

- 전날부터 현재까지의 공식 스픽스 방송·신문 새 자료를 찾는다. 매 회차 `npm run editorial:prepare -- daily 기준일 --refresh`로 새 후보를 갱신한다. prepare daily는 기준일의 전날을 대상으로 하므로 오늘 자료는 다음 날짜를 asOf로 사용한다. 현재 진행 중인 생방송을 완성 방송으로 분석하지 않는다.
- 후보를 직접 골라 editorial:collect로 본문/자막을 수집한다. 같은 URL·ID·내용은 재사용하고, 목록 중복·403·짧은 원문 연결 페이지만 있는 경우에는 추가 취재 대기로 둔다. 주어진 기간 밖 자료는 배경으로 명시한다.
- 하루 총 1~2개의 독립적인 심층 홈페이지 기사를 목표로 한다. 기사별 근거, 반론, 관점, 대안의 조건을 갖추지 못하면 양을 채우지 않는다. 기존 기사와 중복이면 후속 업데이트가 필요한지 먼저 판단한다.
- Gemini 구독 웹 앱은 CUA로 사용한다. 기본 입력은 실제 확보한 자막·기사 본문과 시간표시이며, 자료 범위를 명시해 분석을 요청한다. 영상 링크만 전달한 요청이 지연되면 확보 텍스트를 나눠 전달하는 경로로 전환한다. 각 요청에서3분 이상 응답이 없거나 로그인·한도가 막히면 중단하고 실패를 기록한다. 이 경로도 실패하면 GPT가 원문 대조 분석을 대행하고 실제 작업자를 남긴다. Gemini의 접근 범위가 제공 텍스트뿐이면 영상·음성 분석 완료라고 적지 않는다. 응답은 원자료와 다시 대조하며, 통계의 결측·반올림 원인이나 법적 의무를 추측한 제안은 그대로 채택하지 않는다.
- Claude 구독 CLI는 scripts/claude-desk.mjs로 실행한다. 요청.json에는 id,articleIds,prompt를 둔다. 프롬프트에는 집필 스킬과 실제 원문, 주제별 요구를 포함한다. API 인증 환경변수는 자식 프로세스에서 제외한다. 구독 로그인·한도·실패는 명시적으로 기록한다. Claude가 불가하면 내장 GPT가 실제 집필을 대행하고 기록한다.
- GPT는 원문과 결과를 대조하여 사실·주장·추론 구별, 문체, 중복, 반론을 데스킹한다. 초기 원고를 검토 없이 승인하지 않는다. 이미지 종류와 논지를 맞춘다. 사진은 라이선스·촬영연도·맥락, 삽화는 AI 표시·프롬프트, 도표는 수치·범위를 확인한다.
- save → review → publish로 출고한다. 새 기능을 바꿨다면 관련 테스트, 실제 기사·이미지 검증, build, GitHub push, 공개 페이지 확인까지 수행한다. 검토가 끝난 기사·자산만 커밋하며 원시 자료·구독 인증정보·다른 사용자 변경은 포함하지 않는다.

## 일요일 18:00 마감·월요일 06:00 발행 KST

- 일요일에는 이번 주 월요일~일요일, 월요일에는 직전 월요일~일요일을 대상으로 14개 꼭지·50면을 마감한다. 이미 발행된 호는 수정하지 않고 정정판 ID를 사용한다.
- 편집 중인 호에 서로 다른 질문과 근거를 가진 실제 원고를 편성한다. 방송 순서대로 정리하지 않고 한 주의 연결을 분석한다. 가짜 인터뷰·통계·댓글·서평, 분량 채우기 반복을 금지한다. 홈페이지 기사 전부를 그대로 합본하지 않는다.
- 14개 검토 원고와 발행인의 말로 edition:build를 실행한다. `python scripts/check-edition-render.py output/pdf/호ID/edition.json output/pdf/호ID/proof.pdf --output output/pdf/호ID/render`로 전 면 렌더링·원고 누락·글자 경계를 검사한다. 실제 이미지를 열어 한글, 페이지 넘침, 이미지, 단 나눔, 캡션, QR, 여백, 목차를 확인한다. 넘침은 원고·편성을 고치고 재조판한다. 실제 시각 검수 후에만 pdfReview를 작성한다.
- 완성 PDF만 public/editions에 복사하고 release-edition으로 출고한다. build/push 뒤 공개 PDF와 웹 발행호를 확인한다. 실제 수집·집필이 부족하거나 시각 검수가 끝나지 않았다면 미발행 상태를 유지하고 결함과 남은 취재를 보고한다.
- 전 면 렌더 검사는 `check-edition-render.py`, QR 14개 원출처 일치 검사는 `check-edition-qr.py`로 수행한다. PDF는 벡터 문서이므로 QR 검사는 3배 배율로 렌더링한다. 화면에서 축소한 접촉 인화만으로 QR의 정상 여부를 판단하지 않는다.

## 알림과 운영 조건

변화가 없거나 출고할 내용이 없으면 조용히 종료한다. 실제 새 발행, 의미 있는 실패, 구독 로그인/한도 등 사용자 조치가 필요한 상황만 알린다. 이 채팅의 정기 실행은 현재 PC와 앱이 켜져 있고 프로젝트 폴더를 사용할 수 있을 때 동작한다. 종료 중 놓친 작업은 다음 실행에서 마지막 완료 기록과 편집 중인 호를 확인해 이어 간다. 이 방식은 PC가 꺼진 동안의 서버 자동 발행을 구현했다는 뜻이 아니다.
